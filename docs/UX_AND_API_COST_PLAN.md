# 사용자 편의성과 API 비용 개선

2026-10-06 기준. Alpha v2.1.0에 반영한 항목과 후속 검토를 구분합니다.

## 이번 버전에 반영

- 가격만 있는 주식·ETF·코인도 `renderReport` 템플릿을 사용합니다. 동일한 일곱 탭, 차트 도구, 기술 계산, 시나리오·표결·토론 위치를 유지합니다. 미생성 AI는 모자이크, 미수집 원천 자료는 빈 상태로 표시합니다.
- 기술 지표에서 해당 지표를 켠 일봉 차트로 이동합니다. 설명과 기술로 돌아가기를 제공하고 복귀 시 원래 버튼에 초점을 돌려줍니다.
- 시나리오를 펼치면 미니 차트, 차트 탭에서는 강세·기본·약세 비교를 제공합니다. 미확보 예측 가격을 임의로 생성하지 않습니다.
- 토론 입력·전문가 선택·전송을 한 줄로 합치고 크레딧은 하단에 표시합니다. 계정에 맞춤 전문가를 저장할 수 있습니다.
- 핵심 내용을 먼저 보여주고 전체 토론·세부 근거·전략은 펼쳐봅니다. 즉시 준비되는 화면에는 강제 로딩을 넣지 않습니다.

## 다음 편의성 개선 우선순위

| 순서 | 개선 | 확인할 효과 |
|---|---|---|
| 1 | 모든 자료의 기준 시점과 미수집·갱신 실패·미생성·권한 잠금 상태를 일관된 짧은 표시로 통일 | 빈 화면을 오류나 유료 잠금으로 오해하는 문의 감소 |
| 2 | 지표의 한 줄 해석을 현재 값에 연결하고 용어 설명을 팝업으로 제공 | 설명을 읽기 위해 화면을 이동하는 횟수 감소 |
| 3 | 종목별 최근 탭·기간·열어 본 설명을 복원 | 종목을 다시 열었을 때 설정 반복 감소 |
| 4 | 관심 종목 두 개의 핵심 지표 비교 | 여러 탭을 왕복하는 횟수 감소 |
| 5 | 모바일 키보드가 열린 상태와 실패 후 재시도·입력 복원 검증 확대 | 질문 입력·전송 이탈 감소 |

## Prompt caching 검토 — 아직 미적용

현재 `src/analysis/commentary.ts`와 `src/worker/ask.ts`는 Anthropic SDK를 사용하며 명시적 `cache_control`을 전달하지 않습니다. 리포트 시스템 지침의 첫 줄에는 종목명이 포함됩니다. 채팅은 전문가 설정과 사이트 자료, 대화 이력을 함께 전송합니다.

1. 리포트 공통 시스템 지침에서 종목명을 제거하고 이미 존재하는 user 입력의 종목 필드를 사용합니다. 자산별 추가 규칙은 공통 블록 뒤에 둡니다.
2. 긴 위원회 지침의 마지막 공통 블록에 5분 `cache_control: {type: 'ephemeral'}`을 적용합니다. 출력 스키마와 모델별로 캐시가 나뉘는 점을 반영합니다.
3. 토론 공통 지침, 전문가 설정, 종목 자료를 별도 블록으로 구성합니다. 공통 지침 앞부분을 유지하고 종목·질문·계속 변하는 화면 텍스트는 뒤에 둡니다. 같은 전문가·종목의 반복 요청은 추가 캐시 후보입니다.
4. `cache_creation_input_tokens`, `cache_read_input_tokens`, 일반 입력 및 출력 토큰을 사용 기록에 남깁니다. 일일 비용과 적중률을 먼저 측정하고 1시간 TTL은 실제 요청 간격에 따라 결정합니다.
5. 기존 리포트 생성 중복 방지와 저장 결과 재사용을 유지합니다. Prompt caching은 기존 답변을 재사용하는 기능이 아니므로 결과 재사용과 함께 적용해야 합니다.

첫 캐시 쓰기는 추가 비용이 있고 모델별 최소 토큰 기준이 있습니다. 짧거나 재사용이 드문 요청은 절감 효과가 없거나 비용이 늘 수 있습니다. 출력 비용은 그대로 남습니다. 모델·사용량·적중률을 측정하기 전에는 전체 비용 절감률을 약속하지 않습니다.

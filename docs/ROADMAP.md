## 지킬 원칙

이미 정한 결정은 그대로 두고, 아래 모든 단계가 이 원칙을 따라요.

- **릴리스는 하루 한 번, 저녁에 (G-176)**: 변경을 모아 PR 하나로 올리고, 머지 전에 `/code-review`, tsc, npm test, check-ui를 통과해요. 10/10에는 마이너 버전이 8개 나가서 이 원칙과 어긋났어요.
- **알림은 마이너만 전원에게 (G-177)**: 그래서 마이너 버전은 하루 한 개를 넘기지 않아요.
- **AI 리포트는 위원회 심층 한 종류 (G-168)**: 새 기능도 이 리포트와 만들기 버튼 하나(G-198)를 기준으로 붙여요.
- **숫자와 사실은 요금제와 상관없이 같아요**: 요금제는 공개 범위, 분석 깊이, 질문 권한만 갈라요.
- **결제가 MOCK인 동안에는 살 수 있는 것처럼 보이지 않게 해요**: 실제 결제를 붙이기 전까지 누구도 돈을 낼 수 없다는 걸 화면에서 분명히 해요.

- [x] 네이버 수집에 짧은 재시도 넣기(v3.18.1, G-202): 지금은 재시도가 없어요(`src/sources/naverStock.ts:117` 등). 연결 오류와 5xx만 2번 더 시도해요.
- [x] 머지할 때는 사이트만 다시 만들기(v3.18.1, G-202, 받은 자료 재생): 지금 `daily.yml`은 main에 머지할 때마다 전체 수집을 다시 돌려요. 그래서 10/9에 14번, 10/10에 12번 돌았어요. 전체 수집은 예약 실행(18:30 KST)과 수동 실행 때만 하게 나눠요.
- [ ] 릴리스 리듬 되돌리기: G-176대로 하루 한 번 저녁에 올려요.

**끝난 기준**: 평일 3일 연속으로 실행 경보가 없고, 전체 수집은 하루 1~2번만 돌아요. 10/11 재시도 뒤로 실패는 0건이지만 모두 주말·재생 실행이라, 10/12(월) 예약 실행부터 세요.

## 2단계 · 개인화 흐름

"시장 데일리 → 내 자산 → 위원 입장과 반론 → 질문 → 판단 변경 → 결과 확인"이 제품의 핵심 흐름이에요. 이 흐름을 한 사람 기준으로 이어요. 조각은 이미 있지만 서로 연결돼 있지 않아요.

1. ✅ **공통 프로필** (v3.19.3, G-207): 보기 방식(초보·단타·스윙·장기), 투자 기간, 설명 깊이, 관심 자산을 한 곳에 두고 계정으로 동기화해요. 지금은 설문, 보기 방식, 관심 종목이 따로 있어요. 홈의 내 종목 카드(G-201)가 이 프로필을 읽게 해요.
2. ✅ **내 위원회** (v3.19.7, G-212): 내 전문가 만들기와 답변자 고르기는 이미 있어요. 하지만 홈에서 고른 위원이 리포트와 질문까지 이어지는 구성 화면은 아직 없어요.
3. ✅ **날짜별 질문 기록** (v3.19.3, G-206, 시장 질문만. 종목 질문은 아직): 시장 질문은 리포트 날짜를 받아 그날 자료를 읽어요(`src/worker/api.ts:261`). 그런데 내 토론 기록에서는 모두 `MARKET-DAILY` 하나로 묶여요. 질문에 리포트 날짜를 저장하고, 지난 질문을 누르면 그날 리포트로 돌아가게 해요.
4. ✅ **위원별 판단 결과 추적** (v3.19.8, G-213): G-173의 시나리오와 실제 가격 비교를 위원 단위로 넓혀요. 근거, 전망, 실제 결과가 이어서 보이게 하고, 성적표 화면과 합쳐 한 화면으로 만들어요.

**끝난 기준**: 다른 기기에서 로그인해도 같은 위원과 순서가 나오고, 지난 질문을 누르면 그날 리포트가 열려요.

## 3단계 · 요금제와 권한 정리

크레딧 가격은 이미 `CREDIT_COST` 하나로 모였어요. 하지만 "플러스부터" 같은 최소 요금제 조건은 아직 여러 곳에 흩어져 있어서, 이것부터 합쳐요.

- [x] 기능별 최소 요금제 표 하나 만들기(v3.19.10, G-215, `plans.ts`의 `FEATURES`): 플러스·프로 조건이 `src/worker/api.ts`의 6군데 넘는 곳에 따로 박혀 있어요(234, 235, 558, 713, 862, 1083행 등). 화면 안내, 버튼, 서버 검사가 모두 이 표를 읽게 해요.
- [x] 요금제별로 화면과 API가 같은 조건인지 테스트로 확인하기(v3.19.10, plans.test·api.test): 무료, 플러스, 프로, 맥스, 알파 다섯 가지예요.
- [x] MOCK 표시 점검하기(v3.19.11, G-216): 예전 확인창(`[data-spend]` 처리)은 그리는 버튼이 없어 아무 데서도 뜨지 않았고 지웠어요. 대신 알파 사이트의 결제 화면이 고장 나 있었어요(테스트 결제하기·무료로 바꾸기가 눌러도 아무 일 없음). 알파에서는 "결제를 받지 않아요" 안내와 크레딧 요청 링크, 서버 크레딧 기록을 보여요.
- [x] 실제 결제 연결 설계([PAYMENT_DESIGN.md](PAYMENT_DESIGN.md), G-216): 구독, 취소, 환불, 웹훅을 서버 권한과 맞추는 설계예요. 구현은 개인사업자 등록을 마친 뒤에 해요. 그 전까지 이 단계는 권한 표와 MOCK 표시까지만 해요.

**끝난 기준**: 요금제 조건을 한 곳에서 바꾸면 화면 안내, 버튼, API가 함께 바뀌어요.

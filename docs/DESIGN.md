| 항목 | 값 |

| 상태 | v0 구현 중 (2026-10-03 시작) |

| 결정자 | 한서님 |

## 1. 무엇을 만드나

**SK하이닉스 한 종목의 일일 리포트.** 매일 장이 끝난 뒤 이런 내용을 정적 웹페이지 하나로 보여줘요.
- 오늘 무슨 일이 있었는지: 가격 움직임과 새 공시
- 왜 중요한지: 공시 종류별 설명, 가격 맥락

예측은 v0에 넣지 않아요. 리포트가 자리를 잡은 뒤 보조 정보로 붙여요.

## 2. 결정 (2026-10-03)

|---|---|---|
| G-1 | 0부터 새 저장소로 시작하고, 기존 두 저장소는 읽기 전용으로 보관 | 기존 시스템은 v0에 필요 없는 부분(PAPER 매매, 전략, NARS 파이프라인)이 대부분이었어요 |
| G-2 | 첫 화면은 **일일 리포트** | 예측 숫자보다 "오늘 무슨 일이 있었고 왜 중요한가"가 먼저예요 |

| G-4 | 처음엔 **DB 없이** 저장소 안의 파일에 저장 | 한 종목은 데이터가 작아요. git 이력이 고칠 수 없는 기록이 돼요. 비용은 0원이에요 |
| G-5 | 실행은 GitHub Actions, 화면은 GitHub Pages | 공개 저장소라 둘 다 무료예요. 따로 둘 서버가 없어요 |

## 3. 원칙 (이전 프로젝트에서 가져온 것은 이것뿐)

1. **그 시점에 알 수 있었던 것만 써요.** 모든 기록에 "언제 알았는지"(`retrievedAt`)를 남겨요. 리포트는 만든 시각 이전에 받은 기록만 써요.
2. **과거를 고쳐 쓰지 않아요.** 데이터 파일은 추가만 해요. 같은 키에 다른 내용이 오면 덮어쓰지 않고 실패해요. 그날의 리포트는 한 번 만들면 그대로 보관해요.
3. **근거에는 출처가 붙어요.** 공시마다 DART 원문 링크를 달아요.
4. **매매 권한은 없어요.** 리포트는 투자 권유가 아니에요.
5. **작게 유지해요.** 새 기능은 v0 리포트를 더 좋게 만들 때만 넣어요.

## 4. 구조

```
GitHub Actions (평일 18:30 KST)
  ├─ 가격: Naver 일봉 → data/prices/000660.jsonl
  ├─ 공시: OpenDART list.json → data/disclosures/000660.jsonl
  ├─ 리포트: 위 두 파일 → reports/YYYY-MM-DD.json (그날 한 번만 생성)
  ├─ 페이지: reports/ → site/ (HTML)
  └─ 커밋 + GitHub Pages 배포
```

| 폴더 | 내용 |
|---|---|
| `src/sources` | 외부 데이터 수집 (Naver 가격, OpenDART 공시) |
| `src/store` | 추가만 하는 JSONL 저장 |
| `src/report` | 리포트 계산(순수 함수)과 HTML 렌더링 |
| `src/cli` | 하루 작업을 순서대로 실행 |
| `data/`, `reports/` | 수집 데이터와 생성된 리포트 (커밋됨) |

## 5. 필요한 설정

| 이름 | 어디에 | 비고 |
|---|---|---|
| `OPENDART_API_KEY` | GitHub 저장소 Settings → Secrets → Actions | https://opendart.fss.or.kr 에서 무료로 발급해요. 채팅에 붙여넣지 마세요 |
| GitHub Pages | Settings → Pages → Source: GitHub Actions | |

## 6. 범위 밖 (v0)

예측, 여러 종목, 뉴스(공시 외), 로그인, LLM 해설, 실시간 데이터는 v0 범위 밖이에요. LLM 해설은 비용이 들어서 v0 뒤에 따로 결정해요.

## 7. 확인하지 못한 것

- GitHub Actions 서버(미국)에서 Naver 일봉과 OpenDART에 접속되는지는 첫 실행에서 확인해요. 개발 환경의 네트워크 정책 때문에 여기서는 시험할 수 없었어요.

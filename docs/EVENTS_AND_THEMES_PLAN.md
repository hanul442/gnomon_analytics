# 기업 이벤트·분기 실적·테마 탐색 확장 계획

2026-10-06. 구현 준비 문서이며 아래 신규 데이터 수집·화면은 아직 배포되지 않았습니다. 먼저 즉시 생성의 INVALID_OUTPUT 회귀를 수정합니다.

## 목표와 현재 코드

놓치기 쉬운 공개 정보를 종목별로 묶고, **무엇이 바뀌었는지 · 왜 확인할지 · 원문**을 짧게 보여 줍니다. 기존 요약·수급·펀더멘털·뉴스공시 탭에 같은 이벤트 원본을 연결하고 테마는 검색에서 탐색합니다. 긴 설명 카드와 새 탭을 계속 늘리지 않습니다.

- `src/sources/opendart.ts`는 공시 목록·접수번호·원문 링크를 이미 수집합니다. 배당/지분 API와 공시 본문에서의 세부 거래 사유는 새 작업입니다.
- `src/sources/naverStock.ts`는 분기/연간 실적과 `isEstimate`를 구분합니다. 발표 전에 저장한 컨센서스 이력은 없으므로 현재 값만으로 과거 서프라이즈를 재구성하면 안 됩니다.
- 거래대금은 기존 목록·스크리너 계산에 있습니다. 종목별 이력, 20일 기준 비교와 일관된 수집 상태 표시를 보강합니다.
- AI 근거는 `buildEvidence()`에서 생성됩니다. 이벤트 원문에서 확인된 항목만 근거 ID로 전달합니다.

## 화면별 역할

| 정보 | 먼저 보여 줄 내용 | 연결 위치 | 데이터 조건 |
|---|---|---|---|
| 실적 발표 | 예정/발표됨, 대상 분기, 매출·영업이익, 전년/전분기 변화 | 펀더멘털 → 요약 최근 변화 → 뉴스공시 원문 | 회사 IR 일정·공시 접수 시점 구분; 예정일 없는 회사는 미정 |
| 배당 | 주당 배당금, 공시된 기준일·지급일, 확정/미확정 | 펀더멘털의 배당, 뉴스공시 이벤트, 관심 종목 알림 | 정기보고 배당 내역과 배당 결정 공시 구분; 미공개 날짜를 계산해 만들지 않음 |
| 분기 서프라이즈 | 발표 실제값 vs 발표 직전 저장된 예상값, 차이 | 펀더멘털 분기 표·요약 변화 | 같은 분기·회계 기준·단위·지표; 예상 표본/시점 공개; 과거 예상 없으면 계산 불가 |
| 임원·주요주주 지분 변화 | 보고자, 증감 수량·지분율, 공시일·실제 변동일, 확인된 사유 | 수급의 내부자 공시, 뉴스공시 원문, 요약 중요 이벤트 | 소유증감은 매수·매도와 다름. 증여·상속·보상·분할 등 거래 사유를 원문 확인 전 단정하지 않음 |
| 거래대금 | 실제 거래대금, 20일 중앙값 대비 배수, 거래량·가격 동반 여부 | 수급, 스크리너, 요약 급변 | 원천 실제 거래대금과 `종가×거래량` 추정치를 구분; 장중 값과 종가 값 구분 |
| 테마별 종목 | 테마 설명, 소속 근거, 대표 종목, 거래대금·등락 비교 | 검색 → 테마 → 종목/스크리너 | 산업 분류와 시장 테마 구분; 복수 소속·출처·검수일·직접/간접 노출 표시 |

예시 문구는 실제 수집 값으로만 구성합니다. `예상보다 높게 발표 · 실제 X / 발표 전 예상 Y`, `임원 지분 증가 · 사유 원문 확인`, `거래대금 평소 대비 N배`처럼 짧게 표시하고 상세는 선택했을 때 보여 줍니다. 중요도와 사실/추정 상태는 서로 다른 표시입니다.

## 수집·저장 계약

공통 이벤트: `id, symbol, kind, eventDate, publishedAt, retrievedAt, period, sourceUrl, receiptNo, status, revisionOf, payload`.

- 상태: 예정/확정/정정/미확인/미수집/오류. 원천 조회 실패를 “없음”으로 표시하지 않습니다.
- DART 접수번호로 중복 제거하고 정정 공시가 이전 이벤트를 덮어 지우지 않게 합니다. 공개일, 실제 사건일, 수집일을 보존합니다.
- 분기 실적은 연결/별도와 누적/단독을 구분하고, 동일 회계 범위일 때만 누적 차감으로 단독 분기를 만듭니다. 정정 버전과 원 단위를 저장합니다.
- 서프라이즈율은 `(실제-예상)/abs(예상)`으로 계산하되 예상이 0이거나 누락이면 백분율을 생략합니다. 흑자전환·적자축소는 별도 해석으로 표시합니다. 현재 수정된 예상치를 발표 전 예상으로 대체하지 않습니다.
- 컨센서스의 데이터 이용·재배포 조건과 과거 시점 자료 확보는 구현 전 확인할 의존성입니다. 숫자 없는 뉴스 제목을 실적 수치로 사용하지 않습니다.
- 소유보고의 증감 수량은 순매수량이 아닙니다. 거래별 수량·금액·사유는 원문에 있을 때만 추가합니다.
- 테마 분류는 `themeId, symbol, reason, evidenceUrl, exposure, reviewedAt`로 저장합니다. 초기에는 근거를 확인한 작은 목록부터 시작하고 AI 제안은 검수 전 공개 분류에 넣지 않습니다.
- 전 종목을 매 클릭마다 조회하지 않습니다. 최근 공시 이벤트가 있는 기업·관심 종목·리포트 대상부터 갱신하고 기존 일일 수집/캐시를 재사용합니다.
- AI에는 최신 중요 이벤트의 짧은 구조화 요약과 근거 ID만 추가합니다. 공시 원문 전체를 매 질문에 넣지 않습니다.

## 실행 우선순위 3개

1. **기업 이벤트 기반**: 배당·실적 발표·임원 주요주주 공시를 일관된 이벤트 목록으로 수집. 뉴스공시 타임라인과 펀더멘털/수급의 기존 카드에 연결. 거래대금 실제 값·수집 상태부터 통일. 성공 기준: 원문과 표시 수치가 대응하며 정정·중복·미수집을 구별.
2. **분기 실적과 서프라이즈**: 발표 전 예상치 스냅샷을 먼저 저장하기 시작. 미래 발표부터 검증 가능한 서프라이즈 제공. 성공 기준: 대상 분기, 기준 시점, 연결/별도, 단위가 맞고 미래 정보를 이전 분석에 사용하지 않음.
3. **테마 탐색**: 검색 화면에 테마 진입점, 복수 소속 종목 묶음·스크리너 연결·관심 저장. 성공 기준: 모든 소속에 근거와 검수일이 있으며 모바일에서 기존 메뉴 구조를 유지.

확인 가능한 공개 정보를 기반으로 진행합니다. 아직 수집하지 않은 기능을 화면에 완료된 것처럼 표시하지 않습니다. UI 높이보다 데이터의 시점과 의미 구분을 먼저 해결합니다.
